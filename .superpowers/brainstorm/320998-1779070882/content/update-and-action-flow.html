Update and action flow

How raw observations become agent-usable claims, and how agent decisions become grounded swarm actions.

Observation → belief graph
Robot observes scene
image · LiDAR · point cloud · splat update · pose
↓
Local extractors
occupancy · terrain · objects · hazards · frontiers
↓
Claim builder
normalizes entity IDs, confidence, timestamp, evidence pointer
↓
Fusion/conflict resolver
merge · supersede · conflict · mark stale
↓
Belief graph update
Agent decision → robot action
Agent asks tool
search, route, inspect, allocate
↓
Planner/checker
route feasibility · collision · capability · commitments
↓
Commitment writer
assign task · reserve route/resource · set intent
↓
Robot executor
BT/action primitive/local controller
↓
Execution feedback
complete · blocked · failed · new observation

Key boundary

The agent can propose and coordinate. Local robot controllers still own low-latency safety, collision avoidance, and final execution feasibility.
