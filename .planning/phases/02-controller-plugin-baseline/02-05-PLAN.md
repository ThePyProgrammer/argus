## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| robot velocity buffers -> per-robot controller | Each robot's buffered command becomes a controller command. |
| per-robot controller -> indexed `data.ctrl` writes | Each controller output reaches a subset of shared MuJoCo control array indices. |
| internal refactor -> multi-robot public API | C2/coordinator expects `step() -> dict[str, SensorFrame]`. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-03 | Tampering | `MultiRobotBridge._velocity_to_ctrl`, `step` | mitigate | Use `compute_controller_action` and `apply_controller_target` to validate exact finite `(12,)` targets before indexed writes. |
| T-2-04 | Tampering / Denial of Service | `MultiRobotBridge._controllers`, `step` public contract | mitigate | Create one controller instance per robot id; tests assert distinct instances and unchanged `dict[str, SensorFrame]` return behavior. |
| T-2-01 | Repudiation | Multi bridge controller selection | mitigate | Use explicit `ControllerRegistry.create("analytical_trot")` for each robot; no unknown-id input or silent fallback is introduced in this bridge plan. |
</threat_model>
