## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scenario sample to XML builder | Sampled terrain parameters become MJCF XML. |
| filesystem model_dir to XML builder | Configured model directory is used to locate the known Go2 model assets. |
| environment reset to MuJoCo | Generated XML and reset state create physics model/data. |
| action/push schedule to MuJoCo runtime | Decoded actions and sampled disturbances write into `data.ctrl`/runtime force arrays before physics stepping. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-17 | Tampering | `build_scenario_xml` | mitigate | Use named `ScenarioSample` produced by catalog; do not accept arbitrary scenario/model XML path as scenario selection. |
| T-01-18 | Denial of Service | rough heightfield XML | mitigate | Use bounded `heightfield_size <= 64` from sampling/config validation; tests assert bounded metadata. |
| T-01-19 | Tampering | Go2 source XML | mitigate | Call `patch_actuators_to_position` and mutate parsed XML string only; tests compare source file before/after. |
| T-01-20 | Repudiation | reset/step info after MuJoCo setup | mitigate | Keep sampled parameters, command schedule, disturbance schedule, active push metadata, scenario id, seed, action mode, and `sim_time` in info after model construction and step. |
| T-01-21 | Tampering | `ArgusGo2Env.step` control/force writes | mitigate | Validate/decode actions before writing `self._data.ctrl[:]`, apply push only inside deterministic sampled window through MuJoCo runtime force array, and clear force outside the active window. |
</threat_model>
