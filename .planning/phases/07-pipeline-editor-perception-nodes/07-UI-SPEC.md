# Phase 7 — UI Design Contract

> Visual and interaction contract for the pipeline editor's new perception surface (DetectorNode, Detection3DNode, TrackerNode, new port data types, hot-apply toast, Perception palette section). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope fence:** Pipeline editor only. All new visuals live under `frontend/src/components/pipeline/` or in the shared registries at `frontend/src/utils/nodeDefinitions.ts`. No new standalone sidebar sections, no new routes, no new full-screen surfaces. Every token below extends — not replaces — conventions established by Phase 3 (dark theme dashboard).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual inline-style React; no shadcn, no Tailwind, no CSS-in-JS library) |
| Preset | not applicable |
| Component library | @xyflow/react 12.10.1 (React Flow — nodes, edges, handles) |
| Icon library | none — Unicode glyphs inline (`\u25B6` palette toggle, `\u26A1` live-tunable, `\uD83D\uDD12` restart-required) |
| Font | system default (browser ui-sans-serif); no custom web fonts loaded |

**Styling convention (locked from Phase 3, confirmed in `frontend/src/components/pipeline/NodePalette.tsx` + `NodeInspector.tsx` + `ApplyBar.tsx`):** every component uses inline `React.CSSProperties` objects keyed on hex literals and `px`-suffixed numbers. No className system. Any new component in Phase 7 that invents a CSS framework fails the contract.

### Edge Stroke Styling for New Port Types

Confirmed by inspecting `frontend/src/components/pipeline/EdgeAnimated.tsx`:

- The existing `EdgeAnimated` component uses **static** stroke colors — `#4fc3f7` when `fps > 0`, `#4a4a6a` when idle. It does NOT key stroke color off `PortDataType`.
- **Phase 7 DOES NOT change this convention.** New Detections2D/3D/Tracks edges render with the same accent-cyan-when-active / muted-slate-when-idle treatment. The port-type color is visible only at the socket handle (the 12px circle at each end of the edge).
- Rationale: keeping edge-stroke uniform avoids a 10-way color explosion on the canvas and preserves data-flow affordance (active = cyan, idle = slate). The socket handle is the unambiguous type indicator.
- Downstream note for planner: any change to edge-per-type coloring is explicitly out of Phase 7 scope. If someone wants to revisit (Phase 8+), open a new decision.

### Copy tone rules (locked)

- Sentence case, no ALL CAPS, no exclamation marks (pipeline editor is a power-user surface; avoid cheerleading).
- Verbs are present-tense imperatives: `Apply`, `Restart`, `Switch`, `Update`.
- Error messages must name the failed object: `Pipeline updated in place` (not "Success"); `Hot-swap failed: …` (not "Error"). Consumer must be able to read a single line and know what happened and to what.

Rendered inline inside `ApplyBar` (NOT a new portal). Appears when `POST /api/pipeline/apply` returns `{"status": "hot-applied"}`.

|----------|-------|

| Width | auto, min 240px, max 480px |
| Background | `#1e3a2a` (dark-green surface — matches the success-family on the dark theme) |

| Icon | Unicode check `\u2713` at 12px, color `#4caf50`, `marginRight: 6px`, inline with body text |

| Stacking | Only one toast at a time — a second hot-apply within the 3s window replaces the first (re-render), no queue |

### Palette Layout Ordering

`CATEGORY_ORDER` final order (after Phase 7 insertion):

```
['sensor', 'slam', 'merger', 'perception', 'filter', 'splitter', 'parameter', 'output']
```

## Interaction Contracts

### Drag-to-canvas (unchanged)

Existing `dataTransfer` payload at `NodePalette.tsx:184-191` handles new Perception entries automatically. No interaction changes.

### Hot-apply flow (NEW)

1. User edits `backend` param on a `detector_generic` node in NodeInspector.
2. Pipeline becomes dirty (amber modified dot).
3. User clicks `Apply Pipeline`.
4. Confirmation modal shows (existing or hot-apply variant per planner discretion).
5. `POST /api/pipeline/apply` fires.
6. Server returns one of:
   - `{"status": "hot-applied", "changed": [...]}` → success toast (3s), no overlay, no restart.
   - `{"status": "restarting"}` → existing flow: RestartOverlay mounts until `slam_restart_complete` or `detector_restart_complete` WS.
   - HTTP error → existing inline error.
7. `markApplied()` clears dirty state (both paths).

### Connection validation (NEW — per-edge type check)

1. User drags an edge from port A to port B.
2. React Flow calls `onConnect` → `pipelineStore.onConnect` resolves source port `dataType`.
3. `validate()` runs `findPortTypeMismatches` on the new edge set.
4. If mismatch: validation-errors popup auto-opens (`setShowErrors(true)` — planner decision on auto-open vs. passive), edge remains visible but counted in `validationErrors`.
5. Apply button becomes disabled via existing `!isValid` gating.

Note: per-edge type mismatch does NOT prevent the edge from being created — it's a lint, not a hard block. This matches existing `pipelineValidation` semantics where errors accumulate and gate apply, not edge creation.
