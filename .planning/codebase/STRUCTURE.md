## Key File Locations

**Entry Points:**

- CLI Entry: `dimos` command (installed via pip from DimOS package)
  - Loads blueprints dynamically based on blueprint name argument
  - Resolves GlobalConfig from cascade (defaults → .env → env vars → CLI flags)
  - Calls blueprint build() → deploy modules → loop()

- Python API Entry: Direct imports from `dimos.core`, `dimos.robot.*`, `dimos.agents.*` packages
  - Example: `from dimos.core.blueprints import autoconnect`
  - Assemble blueprint → call build().loop()

**Configuration:**

- `flake.nix`: Development environment declaration
  - Specifies Python 3.12, system dependencies (portaudio, ffmpeg, OpenGL, GStreamer, LCM, CycloneDDS, Open3D)
  - Provides two shells: `default` (blends with system) and `isolated` (fake home, xome-based)
  - Configures environment variables for LD_LIBRARY_PATH, PKG_CONFIG_PATH, GI_TYPELIB_PATH, etc.
  - Builds Docker image with `nix build .#devcontainer`

- `.env` file (not in repo, create locally): Environment variable defaults
  - Used by GlobalConfig cascade (step 2 of 5 precedence)
  - Example: `OPENAI_API_KEY=sk-...`, `ROBOT_IP=192.168.123.161`, `DIMOS_MCP_PORT=9990`

**Documentation:**

- `README.md`: Project overview, quick start, documentation index
- `docs/architecture.md`: Core pattern reference (when understanding how modules/streams/blueprints work)
- `docs/agents.md`: Skill system reference (when writing new skills or integrating agents)
- `docs/robots.md`: Hardware reference (when choosing a blueprint or adding robot support)
- `docs/cli.md`: Configuration reference (when setting environment variables or CLI flags)
- `docs/examples.md`: Usage patterns (when writing Python scripts or running in different modes)
- `docs/claude-code.md`: MCP reference (when integrating with Claude Code)

## Naming Conventions

**Files:**

- Python modules: `snake_case.py` (e.g., `unitree_go2.py`, `spatial_perception.py`)
- Documentation: `kebab-case.md` (e.g., `architecture.md`, `claude-code.md`)
- Configuration: `lowercase.nix` or `UPPERCASE.json` (e.g., `flake.nix`, `settings.local.json`)

**Directories:**

- Module packages: `snake_case` (e.g., `dimos/robot/unitree/`, `dimos/agents/`)
- Blueprint collections: `platform_model` or `platform` (e.g., `go2/`, `xarm/`, `drones/`)
- Feature areas: `snake_case` (e.g., `spatial_perception/`, `motion_planning/`)

## Where to Add New Code

**New Blueprint:**

- **Primary code:** DimOS package (installed via pip) - not editable in this repo
  - Location: `dimos/blueprints/` or `dimos/robot/<platform>/<model>/blueprints.py`
  - Pattern: Function returning Blueprint object, calls autoconnect() with module list
  - Example: `def unitree_go2_custom() -> Blueprint:` returns `autoconnect(camera(), go2_connection(), agent())`

- **Tests:** DimOS package `tests/blueprints/` or robot-specific test directories
  - Pattern: Test blueprint build(), module wiring, configuration injection
  - Framework: pytest with module mocking

- **Documentation:** `.planning/codebase/EXAMPLES.md` or `docs/examples.md` (in this repo)
  - Add runnable example showing usage pattern

**New Module/Skill:**

- **Implementation:** DimOS package, robot or feature-specific subdirectory
  - Location: `dimos/robot/<platform>/skills.py` or `dimos/agents/skills/<skill_name>.py`
  - Pattern: Class inheriting from `Module`, declaring In/Out streams, implementing @skill/@rpc methods
  - Structure:
    ```python
    from dimos.core import Module, In, Out, rpc
    from dimos.agents.annotation import skill

    class MySkills(Module):
        input_stream: In[InputType]
        output_stream: Out[OutputType]

        @rpc
        def start(self) -> None:
            super().start()
            self.input_stream.subscribe(self._on_input)

        def _on_input(self, msg: InputType) -> None:
            # Process and publish
            result = process(msg)
            self.output_stream.publish(result)

        @skill
        def my_skill(self, param: str) -> str:
            """Docstring is mandatory for skills."""
            return f"Executed with {param}"
    ```

- **Tests:** DimOS package `tests/` matching module structure
  - Pattern: Mock In/Out streams, test lifecycle hooks, skill method behavior
  - Framework: pytest with fixtures for streams

- **Documentation:** `docs/agents.md` (if agent skill) or create new `docs/my_feature.md`
  - Document new @skill decorator usage and parameters

**New Transport or Serialization:**

- **Implementation:** DimOS package `dimos/transport/`
  - Location: `dimos/transport/my_transport.py`
  - Pattern: Inherit from Transport base class, implement serialize()/deserialize(), remote_out/remote_in builders
  - Integrate with stream assignment logic

- **Tests:** DimOS package `tests/transport/`
  - Pattern: Unit tests for serialization round-trip, integration tests with module pipelines

**New Configuration Field:**

- **Implementation:** DimOS package `dimos/config.py`
  - Add field to `GlobalConfig` dataclass with default value and help text
  - CLI automatically exposes as `--field-name` flag

- **Documentation:** `docs/cli.md` in appropriate section (Connection, Mode, Visualization, etc.)
  - Add row to flag/env var table with description

**New Documentation:**

- **Location:** `docs/` directory (this repo)
  - Markdown files for user-facing reference
  - Pattern: Clear sections, code examples, configuration tables

- **Location:** `.planning/codebase/` (this repo)
  - GSD analysis documents (ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md)
