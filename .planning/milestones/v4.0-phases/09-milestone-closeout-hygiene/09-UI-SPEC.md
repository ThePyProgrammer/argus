## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline code-adjacent spacing, compact metadata chips if a generated Markdown preview is ever rendered. |
| sm | 8px | Compact element spacing; matches existing frontend control gaps. |
| md | 16px | Default element spacing; use for normal Markdown table/prose grouping in generated docs. |
| lg | 24px | Section padding; use between major closeout sections if rendered in an internal viewer. |
| xl | 32px | Layout gaps; reserve for top-level documentation blocks. |
| 2xl | 48px | Major section breaks only. |
| 3xl | 64px | Page-level spacing only; not expected in Phase 09. |

Exceptions: none for Phase 09. No new interactive touch targets are in scope. If an existing frontend control must be touched incidentally, preserve existing control dimensions and keep clickable targets at least 28px high for parity with current sidebar controls; do not redesign.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Run Closeout Audit` |
| Empty state heading | `No closeout blockers` |
| Empty state body | `All validation metadata and artifact records are ready for milestone closure. Run /gsd-complete-milestone v4.0 next.` |
| Error state | `Closeout audit found blocking artifacts. Review the listed validation, debug, or quick-task records, repair their frontmatter/evidence, then run gsd-sdk query audit-open again.` |
| Destructive confirmation | None. Phase 09 must not introduce destructive UI actions. If a future closeout tool offers bulk archive/delete, require explicit typed confirmation: `Type CLOSEOUT to archive resolved artifacts.` |

**Interaction contract for this phase:**

- Primary workflow is CLI/documentation driven, not browser driven.
- The acceptance interaction is `gsd-sdk query audit-open`; success is no blocking open items.
- If any status text is added to generated docs, use evidence-first language: `Resolved with evidence`, `Moved out of v4.0 closeout path`, or `Still blocking closeout`.
- Do not use vague success copy such as `Looks good` or `Done` without naming the audit gate and artifact category.
- Do not mark human-verification debug sessions as resolved in UI/status copy unless the underlying artifact contains matching resolution evidence.
