<objective>
Close the Phase 7 verification blocker where `eval-locomotion --matrix-config` silently overwrites JSON scalar values with argparse defaults.

Purpose: Phase 7 already made the evaluation layer reject unsupported action modes before side effects, but the CLI matrix-config path bypasses that contract by replacing loaded `action_mode`, `max_episode_steps`, `sim_steps_per_frame`, and `heightfield_size` with parser defaults. This plan makes CLI scalar overrides explicit-only so matrix-config runs cannot produce misleading artifacts.
Output: CLI merge-semantics regressions, fixed argparse defaults/merge logic, portable subprocess invocation in CLI tests, and a small docs markup cleanup.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JSON matrix config -> CLI merge layer | User-provided matrix-config scalar values cross into `src/main.py` before evaluation validation. |
| CLI scalar flags -> matrix override layer | Explicit user flags override saved matrix values and can change action mode/runtime dimensions. |
| CLI/evaluation -> artifact filesystem | Invalid action-mode requests must fail before output-root side effects or misleading artifacts. |
| Test subprocess -> local Python environment | CLI tests execute `python -m src.main`; using the active interpreter avoids machine-specific `.venv` assumptions. |
| Docs/help -> user behavior | Public contract text influences whether users expect unsupported action modes to produce artifacts. |
