**2. Add a docstring note to BridgeProtocol about its scope**

The `BridgeProtocol` in `src/bridge/sensor_types.py` (line 81) defines:
- `start() -> SensorFrame`
- `step() -> SensorFrame`
- `set_velocity(linear, angular) -> None`
- `stop() -> None`

This matches `MuJoCoBridge` (single-robot). `MultiRobotBridge` has a different API:
- `start() -> dict[str, SensorFrame]`
- `step() -> dict[str, SensorFrame]`
- `set_velocity(robot_id, linear, angular) -> None`

The Protocol is used by `ExplorationLoop` and `RobotInstance` -- both of which work with single-robot bridges (each RobotInstance wraps a robot-specific view). So the Protocol is correct for its consumers.

Add a docstring clarification to BridgeProtocol:
```python
class BridgeProtocol(Protocol):
    """Minimal interface for a single-robot simulation bridge.

    Used by ExplorationLoop and RobotInstance. MuJoCoBridge implements
    this directly. For multi-robot scenarios, the Coordinator provides
    per-robot bridge wrappers that satisfy this protocol -- MultiRobotBridge
    itself has a different (dict-based) API and does NOT implement this protocol.
    """
```

This resolves the audit finding by documenting the intentional design, not by changing code that works correctly.
