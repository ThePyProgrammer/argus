# AGIBOT X2 / AgiBot Humanoid Simulation Asset & Repository Survey

Accessed date for all sources: **2026-04-30**.

Scope: concrete public assets and code repositories relevant to AGIBOT X2 / AgiBot humanoid development: URDF, MJCF/XML, USD, meshes, Isaac Sim/Isaac Lab, MuJoCo, ROS/ROS 2, teleoperation, calibration/kinematic data, and robot datasets. This report intentionally avoids broad swarm-control methodology except where assets directly help multi-robot simulation, deployment, or integration.

## 3. Findings by simulator / toolchain

### 3.1 Isaac Sim / Isaac Lab

- **Best X2-specific source:** `wxy9446-debug/Agibot-x2_stand_train` contains X2 USD assets and Isaac Lab configuration. The inspected config directly points Isaac Lab `ArticulationCfg` at an absolute USD path such as `X2_URDF-v1.3.0/x2_ultra/x2_ultra.usd`, with variants `x2_fist`, `x2_ultra`, and `x2_ultra_simple_collision` plus separate `configuration/*_base.usd`, `*_physics.usd`, `*_robot.usd`, and `*_sensor.usd` layers [4]. This is the most directly useful public X2 asset set for Isaac Lab standing/walking experiments.
- **Official AgiBot simulator stack:** `AgibotTech/genie_sim` README says v3.0 updated to **Isaac Sim 5.1.0**, provides **USD and URDF files of Agibot Genie G2**, supports whole-body control, 3DGS scene reconstruction to USD, synthetic data, benchmark/evaluation, teleoperation, and RLinf distributed reinforcement learning support [1]. This is mature and official, but X2 geometry is not present in the inspected official tree.
- **Scene/object assets:** `GenieSimAssets` offers 5000+ sim assets and robot folders for G1/G2, but exact file extensions are not exposed by the Hugging Face page. It is still the most relevant official asset pool for Isaac Sim scenes and objects, subject to non-commercial CC BY-NC-SA restrictions [2].
- **Compatibility note:** USD is native for Isaac Sim/Isaac Lab. The third-party X2 USD packages appear immediately useful, but should be audited for scale, inertias, joint limits, sensors, actuator definitions, and whether USD layers were generated from an official X2 URDF bundle [4][5].

### 3.2 MuJoCo / MJCF

- **X2 assets:** `Agibot-x2_stand_train` includes `x2_fist.xml`, `x2_hand.xml`, and `x2_ultra.xml`; inspection of `x2_ultra.xml` showed a MuJoCo model named `x2t2.5`, `meshdir="./meshes"`, 0.001 timestep, mesh assets, **94 `<joint>` tags**, **32 bodies**, and **31 actuators/motors/position actuators** [4].
- **X2 ROS package mirror:** `Gautam1704/Agibot-X2-Humanoid` includes the same-named XMLs under `src/humanoid_urdf/urdf/` and STL meshes under `src/humanoid_urdf/meshes/`; inspection similarly counted 94 joints, 32 bodies, and 31 actuators in `x2_ultra.xml` [5].
- **Official X1 precedent:** `agibot_x1_train` includes X1 `resources/robots/x1/mjcf/.../xyber_x1_serial.xml`, `xyber_x1_flat.xml`, STL meshes, URDF, Isaac Gym training, and MuJoCo sim2sim validation (`scripts/sim2sim.py`) [8]. `agibot_x1_infer` contains the X1 sim module with MuJoCo headers/libs and model assets [9]. These are useful for control-stack patterns, not X2 geometry.
- **Genie Sim MuJoCo bridge:** `genie_sim` contains `source/geniesim/rl/mujoco/mujoco_ros_node.py`, indicating MuJoCo integration in the RL stack, but the main official robot assets inspected are URDF/USD/USDA/Isaac-oriented rather than X2 MJCF [1].

### 3.3 ROS / ROS 2 / URDF / RViz / Gazebo-style visualization

- **Best licensed X2 URDF package:** `Gautam1704/Agibot-X2-Humanoid` is Apache-2.0 and contains a ROS 2 Python package named `humanoid_urdf`, `package.xml`, RViz config, launch files (`display.launch.py`, `rsp_launch.py`, `actual_robot.py`), STL meshes, X2 URDF variants (`x2_fist.urdf`, `x2_hand.urdf`, `x2_ultra.urdf`, `x2_ultra_simple_collision.urdf`) and XML variants [5]. The package metadata is minimal (`TODO` description), so asset quality needs validation.
- **X2 teleop integration:** `sorrowfeng/aimdk` contains ROS 2 messages/services/actions for X2 HAL, motion control, face UI, interaction, audio, teleop bridge data (`VRData`, `VRControllerState`, `VRControllerAction`, `VRNetwork`), and C++/Python examples. The teleop guide documents `Develop_MC` mode, `/aima/hal/joint/arm/command`, `/aima/hal/joint/hand/command`, UDP JSON structure, coordinate mapping, Ruckig smoothing at 100 Hz, and a `parse_x2_urdf.py` script extracting arm kinematics from an X2 URDF [6]. Useful for turning URDF geometry into robot-side teleop/calibration experiments.
- **X2 HTTP/MQTT robot bridge:** `liulhs/AGIBOT` wraps ROS 2 services behind Flask endpoints and MQTT topics. It is useful for multi-robot orchestration experiments if each robot exposes a local HTTP/MQTT motion API, but it is not a simulator or URDF source except for generated docs references [7].
- **Official hand SDK:** `Omnihand-2025-SDK` includes URDF/xacro and STL meshes for left/right OmniHand plus ROS 2 RViz configs and a C++/Python SDK. This can complement X2 end-effector modeling if the X2 hand matches or if a proxy hand is acceptable [11].

### 3.4 USD / scene assets / datasets

- **Official large-scale environment pool:** `GenieSimAssets` is the main concrete asset dataset, with 5000+ objects and 29.4 GB total size, plus backgrounds, interaction, real2sim, and G1/G2 robot folders [2]. Usefulness is high for building diverse manipulation scenes around X2 once X2 USD/URDF is imported into Genie Sim/Isaac.
- **Genie Sim benchmark scenes:** `genie_sim` contains many `scene.usda` benchmark configs under tasks such as `bimanual_chip_handover`, `clean_the_desktop`, `open_door`, `pack_in_supermarket`, `pick_block_*`, etc. These are concrete USDA scene definitions useful for X2-based manipulation evaluation after retargeting robot configs [1].
- **X2 USD variants:** `Agibot-x2_stand_train` is the only inspected source with direct X2 USD assets. It provides full robot USD and component configuration USDs for physics/robot/sensor/base layers [4]. No official X2 USD release from AgibotTech was found in the inspected public org repositories.

### 3.5 Teleoperation, calibration, and motion-control data

- **Teleop:** `sorrowfeng/aimdk` is the strongest direct X2 teleop asset. It has UDP VR bridge, C++ IK node, Ruckig smoothing, demo keyboard mode, hand command mapping, and documented ROS 2 topics/services [6].
- **Motion-control bridge:** `liulhs/AGIBOT` documents X2 modes, preset motions, LinkCraft motion concepts, REST/MQTT control, and Jetson Orin NX deployment. Its docs are valuable for deployment and swarm-control plumbing, but legal/provenance and operational safety need scrutiny [7].
- **Official AgiBot teleop/data collection:** `genie_sim` contains `scripts/autoteleop.sh`, `scripts/autoteleop_post_process.sh`, `source/teleop`, `source/data_collection`, and conversion to LeRobot (`convert_agibot_to_lerobot.py`), which are useful for data collection and policy training, but inspected robot configs target G1/G2 rather than X2 [1].
- **Calibration:** No dedicated public X2 calibration dataset was found. Available calibration-like material is indirect: URDF joint origins/limits, X2 AIMDK docs in third-party repos, VR coordinate mappings, and kinematic extraction scripts [4][5][6][7].

## 4. Gaps and risks

1. **No official AgibotTech X2 simulation repository found.** Public AgibotTech repos include official X1, G1/G2 Genie Sim, and OmniHand assets, but not a clearly official `agibot_x2_*` simulation repo. The best X2 assets found are third-party [4][5][6][7].
2. **License risk is severe for the most complete X2 Isaac Lab package.** `wxy9446-debug/Agibot-x2_stand_train` has no detected license despite containing the most useful X2 USD/URDF/MJCF package [4]. Treat as reference-only unless permission/provenance is clarified.
3. **Third-party X2 asset provenance is unclear.** `Gautam1704/Agibot-X2-Humanoid` is Apache-2.0, but the source of meshes/URDF/XML is not documented in the minimal README/package metadata. Verify whether assets came from an official X2 URDF release and whether redistribution is allowed [5].
4. **Official Genie Sim is not X2-specific.** It is mature, official, and useful for Isaac Sim/benchmarks, but inspected robot models are G1/G2; X2 retargeting/import work remains [1][2][3].
5. **GenieSimAssets license is non-commercial/share-alike.** CC BY-NC-SA 4.0 may block commercial use and contaminate derived scene distributions [2].
6. **Model fidelity needs physics audit.** X2 MJCF/URDF/USD assets should be checked for mass/inertia plausibility, collision simplification, actuator gains, sensor placement, joint limits, mesh scale, foot contact definitions, and consistency across URDF/XML/USD variants [4][5].
7. **Simulator conversion paths are possible but not zero-cost.** URDF can feed ROS/RViz and Isaac import; MuJoCo XML is directly useful for MuJoCo; USD is native to Isaac. But round-tripping can lose actuator/contact/sensor semantics. For swarm simulation, standardize one canonical X2 asset source and generate/import others reproducibly [4][5].
8. **Teleop/control repos are operationally useful but unsafe if treated as generic APIs.** X2 motion mode transitions, `Develop_MC` mode, preset motions, and hand/arm command topics can move real hardware. Any swarm-control integration must sandbox, simulate first, and add robot identity, rate limits, emergency-stop semantics, and collision/geofence checks [6][7].
9. **No public multi-X2 swarm asset pack found.** Found assets support individual X2 modeling/control. Multi-robot simulation will require duplicating X2 USD/URDF/MJCF instances, namespace isolation, per-robot ROS 2 domains/namespaces, and scene-scale asset management; none of the inspected repos directly solves this.

## 5. Practical recommendations for AGIBOT X2-based development

- **For immediate X2 simulation experiments:** start by auditing `Gautam1704/Agibot-X2-Humanoid` because it has Apache-2.0 metadata and URDF/XML/STL assets [5]. Use `wxy9446-debug/Agibot-x2_stand_train` as a technical reference for Isaac Lab USD configuration, not as redistributable code until licensing is resolved [4].
- **For Isaac Lab:** compare `x2_ultra.usd` and `x2_ultra_simple_collision.usd` from [4] against the URDF/XML in [5]. Validate articulation loading, joint order, actuator mapping, and collision stability. Then import Genie Sim scenes/assets around the X2 robot [1][2].
- **For MuJoCo:** use `x2_ultra.xml` / `x2_hand.xml` / `x2_fist.xml` from [4] or [5] and verify actuator and contact parameters before PPO/RL. Use official X1 `sim2sim.py` patterns as implementation precedent [8][9].
- **For ROS 2 teleop/control:** use [6] for message definitions, VR bridge, IK parsing, and hand command examples. Use [7] only after security review if HTTP/MQTT robot-control endpoints are needed.
- **For manipulation scenes:** use Genie Sim / GenieSimAssets for objects, tasks, and synthetic data, while keeping license constraints explicit [1][2][3].
