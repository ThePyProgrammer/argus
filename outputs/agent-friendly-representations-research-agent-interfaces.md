# Agent Interfaces to Spatial World Representations

## Executive takeaways

- Most LLM/VLM embodied-agent systems do not reason directly over raw geometry at decision time. They typically mediate the world through language action sets, value maps, scene graphs, object/affordance graphs, simulator APIs, PDDL/state abstractions, or learned observation-to-action tokens.
- Direct 3D interfaces are emerging in 3D-LLMs and embodied generalist agents, but even these commonly use extracted 3D features, rendered multi-view features, object-level datasets, or 3D vision-language alignment layers rather than exposing raw point clouds as planner state.
- For robotics planning/action grounding, the dominant pattern is a split architecture: foundation models supply semantic/task reasoning, while explicit controllers, affordance models, value maps, or planners enforce feasibility.
- 3D scene graphs and semantic/language maps are a strong middle ground: they retain spatial relationships and object identity while being compact and queryable by language or symbolic planners.
- Simulator APIs such as Habitat and AI2-THOR expose configurable sensors, actions, tasks, and benchmark state; they act as mediated interfaces for embodied agents rather than as native LLM world models.
- Evidence is uneven: papers often demonstrate that mediated interfaces help, but fewer provide apples-to-apples comparisons between raw 3D input, dense semantic maps, scene graphs, and symbolic state for the same agent and task.

## Detailed findings

### 1. LLM robotic planners usually need a grounding layer between language and physical state

SayCan is a canonical example of an LLM planner that is deliberately not allowed to act from language alone. The LLM ranks useful next steps, but robot affordance/value functions estimate which skill is feasible in the current state; the chosen action must be both semantically useful and executable [Do As I Can, Not As I Say](https://arxiv.org/abs/2204.01691). This is an agent-friendly interface because it compresses the world into a list of candidate natural-language skills with feasibility scores. It is not direct 3D reasoning; the robot's perception, skills, and value functions absorb the geometric/physical grounding burden.

Code as Policies exposes the world through APIs: object detectors, control primitives, and geometry/math libraries such as NumPy and Shapely [Code as Policies](https://arxiv.org/abs/2209.07753). The LLM becomes a program synthesizer over callable affordances rather than a model that directly manipulates point clouds or voxels. This pattern is attractive because code can express loops, conditionals, feedback, and geometric computations; its weakness is that the callable world model has to be engineered and trusted.

ProgPrompt similarly wraps situated planning in program-like specifications of available actions and objects, with example programs to constrain the LLM's output [ProgPrompt](https://arxiv.org/abs/2209.11302). Inner Monologue extends the interface by returning success checks, scene captions, and human feedback as language, enabling closed-loop plan revision [Inner Monologue](https://arxiv.org/abs/2207.05608). Both replace direct spatial state with textual or programmatic state summaries.

### 2. 3D value maps are a bridge between free-form language and motion planning

VoxPoser is one of the clearest examples where the agent interface is genuinely spatial but still mediated. The LLM decomposes an instruction, uses VLM outputs, writes code, and constructs composable 3D value maps for affordances and constraints; a model-based planner then turns those maps into trajectories [VoxPoser](https://arxiv.org/abs/2307.05973). Unlike text-only planning, the planner receives a 3D field that can encode where to move or avoid. Unlike direct point-cloud reasoning, the LLM does not consume raw geometry as its native representation; it orchestrates tools that create planner-readable value fields.

This design suggests a practical pattern for embodied agents: let foundation models infer semantic constraints, then project those constraints into continuous spatial objectives. It is especially relevant for manipulation, where symbolic task plans are often too coarse and raw point clouds are too low-level for an LLM.

### 3. Semantic maps and language-grounded maps make spatial worlds queryable by language

VLMaps combines 3D reconstruction with pretrained vision-language features to build a map that can localize open-vocabulary language targets [Visual Language Maps](https://arxiv.org/abs/2210.05714). The interface for the agent is not a raw reconstruction but a language-indexed spatial map: commands are translated into target categories/phrases, and the map returns places to navigate to. It also supports embodiment-specific obstacle maps from category lists, showing how the same semantic map can be reinterpreted for different robots.

Language-grounded maps are attractive because they preserve metric/spatial grounding while exposing a semantic query interface. They sit between dense 3D representations and symbolic planners: richer than PDDL symbols, more planner-friendly than raw point features, but dependent on map quality, segmentation, viewpoint coverage, and visual-language model grounding.

### 4. 3D scene graphs are the most planner-readable 3D abstraction surveyed

3D Dynamic Scene Graphs encode the world as a multi-layer graph containing places, objects, walls, rooms, robots, humans, and relations such as inclusion and adjacency [3D Dynamic Scene Graphs](https://arxiv.org/abs/2002.06289). Their purpose is explicitly actionable spatial perception: long-term autonomy, planning, human-robot interaction, and prediction need entities and relations, not just dense geometry.

ConceptGraphs updates this idea with open-vocabulary semantics by combining 2D foundation-model outputs into compact 3D scene graphs [ConceptGraphs](https://arxiv.org/abs/2309.16650). The paper explicitly contrasts graph-structured representations with dense per-point feature maps, arguing that dense maps do not scale well in larger environments and lack semantic spatial relationships [ConceptGraphs](https://arxiv.org/abs/2309.16650). Context-Aware Entity Grounding with OVSG shows the query interface: free-form text descriptions can be grounded to objects, agents, and regions in an open-vocabulary 3D scene graph [Context-Aware Entity Grounding with Open-Vocabulary 3D Scene Graphs](https://arxiv.org/abs/2309.15940).

The key interface benefit is compositionality. An LLM or planner can ask for "the mug on the table near the couch" because objects, rooms, and relationships are first-class. The tradeoff is that scene-graph construction is a perception problem; errors in object association, relation extraction, or region segmentation become planner errors.

### 5. Navigation systems often use trajectories, images, text observations, or topological candidates rather than explicit 3D state

LM-Nav links GPT-3, CLIP, and ViNG for long-horizon navigation without fine-tuning or language-annotated robot data [LM-Nav](https://arxiv.org/abs/2207.04429). Its interface is a pretrained-model pipeline over language, image goals, and goal-conditioned navigation trajectories, not an explicit 3D map.

NavGPT goes even further toward mediation: it is a purely LLM-based instruction-following navigation agent that reasons over text versions of visual observations, navigation history, and candidate future directions [NavGPT](https://arxiv.org/abs/2305.16986). It can decompose instructions and track landmarks, but the paper reports that zero-shot Room-to-Room performance remains below trained baselines [NavGPT](https://arxiv.org/abs/2305.16986). This is a useful caution: a text interface is convenient for LLM reasoning, but it can discard spatial detail that trained multimodal policies exploit.

### 6. Planner-readable symbolic state remains useful, but only after perception and grounding have done their job

LLM+P shows a clean interface between LLMs and classical planners: translate natural-language planning tasks into PDDL, invoke an optimal planner, and translate the result back into natural language [LLM+P](https://arxiv.org/abs/2304.11477). This is compelling for long-horizon task structure because the planner can enforce preconditions/effects and optimality. However, PDDL is a mediated symbolic abstraction. It does not solve how a robot obtains reliable object poses, affordances, regions, or continuous constraints from a messy 3D world.

A practical architecture often needs both: perception/semantic mapping to populate symbolic predicates, then a planner to sequence actions, then continuous controllers/value maps to execute each step.

### 7. End-to-end embodied multimodal models hide the interface inside learned tokens

PaLM-E interleaves visual, continuous state-estimation, and text encodings in "multimodal sentences" for embodied reasoning [PaLM-E](https://arxiv.org/abs/2303.03378). RT-2 encodes robot actions as text tokens and co-trains on robot trajectories plus web-scale VLM tasks [RT-2](https://arxiv.org/abs/2307.15818). MultiPLY uses action tokens, state tokens, and object-centric multisensory representations in a 3D environment [MultiPLY](https://arxiv.org/abs/2401.08577). LEO uses 3D vision-language alignment and 3D vision-language-action instruction tuning for 3D captioning, QA, embodied reasoning, navigation, and manipulation [An Embodied Generalist Agent in 3D World](https://arxiv.org/abs/2311.12871).

These systems are closer to direct embodied perception than symbolic planners, but they still do not generally expose raw point clouds/voxels/splats as transparent planner state. Instead, they learn encodings and token interfaces. This can improve generalization and reduce hand-engineering, but it makes state inspection, safety constraints, and formal planning harder.

### 8. 3D-LLMs are the clearest direct-3D trend, but they still rely on feature mediation

3D-LLM ingests 3D point clouds plus features extracted through rendered multi-view images and uses a 3D localization mechanism over 2D VLM backbones [3D-LLM](https://arxiv.org/abs/2307.12981). That is significantly more direct than text-only or PDDL interfaces: 3D scene data enters the language model pipeline. But the interface is still not "LLM reasons over raw point cloud coordinates alone." It is a learned 3D feature pipeline, often leveraging 2D foundation-model representations.

The broader pattern is that raw geometry is rarely the final cognitive substrate. Point clouds and reconstructions are used to produce features, maps, entities, relations, or action/state tokens that are friendlier to LLM/VLM reasoning and robotic planning.

### 9. Simulators are world-interface providers, not merely data generators

Habitat divides the embodied-agent interface into Habitat-Sim, a high-performance photorealistic 3D simulator with configurable agents/sensors, and Habitat-API, a high-level library for task setup, training, and benchmarking [Habitat](https://arxiv.org/abs/1904.01201). AI2-THOR similarly exposes near-photorealistic indoor scenes where agents can move and interact with objects [AI2-THOR](https://arxiv.org/abs/1712.05474). CALVIN provides a benchmark for long-horizon language-guided manipulation with language, vision, and action sequences [CALVIN](https://arxiv.org/abs/2112.03227).

For LLM/VLM agents, simulator APIs often become the practical spatial interface: observations are returned as RGB/depth/state, actions are discrete or continuous commands, and task success is programmatically checked. This is mediated abstraction through an environment API, even when the simulator internally stores exact 3D geometry and object state.

## Contradictions / gaps

- **Direct 3D vs mediated abstraction is not a binary.** VoxPoser uses 3D value maps [VoxPoser](https://arxiv.org/abs/2307.05973), VLMaps uses 3D reconstruction with language features [Visual Language Maps](https://arxiv.org/abs/2210.05714), and 3D-LLM ingests point clouds/features [3D-LLM](https://arxiv.org/abs/2307.12981). Yet all three still rely on mediation layers: code, VLM features, maps, or feature extractors.
- **Scene graphs promise planner-readability but depend on hard perception problems.** ConceptGraphs and OVSG expose language-queryable object/relationship graphs [ConceptGraphs](https://arxiv.org/abs/2309.16650), [Context-Aware Entity Grounding with Open-Vocabulary 3D Scene Graphs](https://arxiv.org/abs/2309.15940), while DSGs provide multi-level spatial structure [3D Dynamic Scene Graphs](https://arxiv.org/abs/2002.06289). The gap is robust, dynamic, real-time graph construction under occlusion and changing scenes.
- **Text-only navigation interfaces are LLM-friendly but may underuse spatial detail.** NavGPT demonstrates explicit language reasoning but remains below trained baselines in zero-shot R2R [NavGPT](https://arxiv.org/abs/2305.16986). This suggests a tradeoff between interpretability/promptability and geometric fidelity.
- **End-to-end VLA models and symbolic/planner systems optimize different desiderata.** RT-2 and PaLM-E reduce manual interface design by learning observation/action representations [RT-2](https://arxiv.org/abs/2307.15818), [PaLM-E](https://arxiv.org/abs/2303.03378). LLM+P, SayCan, and Code as Policies make constraints/actions more inspectable [LLM+P](https://arxiv.org/abs/2304.11477), [Do As I Can, Not As I Say](https://arxiv.org/abs/2204.01691), [Code as Policies](https://arxiv.org/abs/2209.07753). There is no settled standard for combining learned 3D perception with formal planner state.
- **Gaussian splats were not found as a dominant agent interface in the surveyed sources.** They are important for rendering/reconstruction, but within this task boundary the stronger agent-facing abstractions are maps, graphs, APIs, value fields, and tokens.
- **Benchmark comparability is weak.** Sources cover different tasks: manipulation, navigation, embodied QA, simulator benchmarks, 3D captioning, and planning. Few directly compare point-cloud-native models against graph/map/symbolic interfaces under identical robot tasks.
